01 · Responsibility Boundary

Agent 能做什么，不能做什么

把能力边界写进产品，不靠提示词自觉。模型输出始终是不可信建议，只有经过领域工具、确认点和校验器的产物才能进入科研主链。

Agent can

理解、编排、解释

✓理解自然语言意图，发现缺失信息并主动追问
✓生成候选研究方案、方法与行动计划
✓调用白名单工具，组织跨任务执行
✓基于 Verified Result 解释结果和撰写文本
Agent cannot

编造、越权、替代判断

×编造文献、数据、统计数值或期刊动态信息
×绕过领域服务直接读写数据库或对象存储
×自行计算或修改 HR、OR、P 值、CI、AUC
×未经确认执行清洗、分析、正式导出或外发
!中段红线：Agent 负责理解分析目标、推荐方法、编排执行和解释结果；真正的清洗、统计与绘图必须由确定性 Python/R Worker 完成。
02 · Unified Execution Model

所有 Agent 共享一套执行骨架

开放式对话被收敛成可观测状态机。每一步都有输入、工具、输出和风险等级，关键节点由人做最终决定。

STEP 01

信息收集

读取用户输入、项目资产与授权上下文。

STEP 02

计划生成

结构化意图、缺失项和候选行动。

STEP 03

策略校验

权限、工具白名单、风险和数据边界。

HUMAN GATE

等待确认

展示影响、选择与风险，等待用户决定。

STEP 05

工具执行

调用领域服务和确定性执行器。

STEP 06

结果校验

Schema、数值、引用、来源和状态检查。

STEP 07

交付衔接

登记资产并建议下一项任务。

R0 · READ查看、检索、解释；执行并审计。
R1 · REVERSIBLE保存草稿和候选计划；可版本回退。
R2 · COMPUTE清洗、分析、调模；执行前强确认。
R3 · EXPORT正式导出或外发；权限与合规闸门。
03 · Agent Task Map

12 项 Agent，按论文真实流程覆盖科研全周期

每个任务都定义了工具、流程、信息来源、输出、跨会话记忆、异常边界和上下游衔接。展示顺序按选题、证据、方案、伦理、执行、数据、统计、写作、投稿展开。

04 · Human-in-the-loop

把人放在真正重要的决策点

确认点不是交互负担，而是科研责任边界。越接近数据变更、统计结论和正式外发，确认要求越强。

12

类强制确认

每个 Agent 至少有一个明确的人机中断点。

选题 → 证据 → 方案 → 伦理 → 执行 → 数据 → 统计 → 写作 → 投稿，风险逐步升级。

05 · Shared Domain Core

10 个 Agent，不做 10 套系统

Agent 只负责意图和编排。所有科研事实、规则、计算与产物都落在共享领域内核，工作流入口也复用同一套能力。
