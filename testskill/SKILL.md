## Output Format

输出必须严格按照以下结构化报告格式，确保用户获得可直接阅读的决策型内容，而非简单的文字描述。

### 1. 热点总览表

以表格形式展示所有识别到的热点主题及其热度指标。

| 热点主题 | 热度指数 | 趋势方向 | 代表性论文数 | 活跃年份 |
|---------|:-------:|:--------:|:-----------:|:--------:|
| [主题1] | ★★★★★ | 📈 上升 | 45篇 | 2023-2026 |
| [主题2] | ★★★★☆ | ➡️ 持平 | 28篇 | 2022-2026 |
| [主题3] | ★★★☆☆ | 📉 下降 | 12篇 | 2020-2024 |

- 热度指数：基于发文量、被引频次、顶刊占比综合评定，最高 ★★★★★
- 趋势方向：近 3 年发文量变化趋势（📈 上升 / ➡️ 持平 / 📉 下降）
- 代表性论文数：该热点主题下匹配到的核心文献数量
- 活跃年份：该热点有持续产出的年份范围

### 2. 热点详情分析

每个热点独立展开，包含热度评级、趋势说明、子方向构成及关键论文。

### 3. 研究空白识别

分析当前文献覆盖的不足区域，识别未被充分探索的方向。

| 研究空白 | 潜在价值 | 可行性 | 原因说明 |
|---------|:--------:|:------:|:--------:|
| [空白 1 - 未被充分探索的方向] | 高 | 中等 | 相关文献 < 10 篇，但临床需求明确 |
| [空白 2] | 中 | 高 | 已有成熟工具，但尚未应用于该领域 |

- 潜在价值：高 / 中 / 低，基于未满足的临床或基础研究需求判断

基于前序分析，给出具体可落地的研究切入建议。

# Research Hotspot Analysis

## When to Use

- 用户给出疾病名、靶点、技术路线或研究主题，希望快速看到当前研究热点。
- 用户需要把近期文献按关键词和主题聚类，找出最值得继续深挖的方向。
- 用户想要一份带代表文献的 Markdown 热点分析报告，供选题或综述写作使用。

## When Not to Use

- 用户只需要单篇文献检索或简单参考文献列表时，不要使用本技能。
- 如果没有明确的疾病、主题或检索范围，不要直接开始聚类，先让用户补充主题边界。
- 如果环境无法访问本 skill 所依赖的脚本或检索数据，不要伪造热点结果。

## Required Inputs

| 字段 | 必填 | 格式/来源 | 示例 | 缺失时处理 |
|---|---|---|---|---|
| `topic` | 是 | 文本 | `lung cancer immunotherapy` | 缺失时停止并要求补充主题 |
| `time_range` | 否 | 时间范围 | `last 5 years` | 未提供时默认近期文献 |
| `focus` | 否 | 文本 | `mechanism`, `clinical translation` | 未提供时按综合热点输出 |

## Workflow

1. 使用 `scripts/analysis_ops.py` 的 `search_pubmed` 搜索相关文献并获取 PMID 与基础元数据。
2. 对返回的 `medline_texts` 执行 `word_frequency`，统计高频关键词或 MeSH 术语。
3. 结合 `references/prompt_templates.md` 中的 hotspot 提示词，把高频关键词聚类成 3-6 个热点主题。
4. 使用 `match_keywords` 将代表文献映射到各个主题，避免主题和证据脱节。
5. 对每个主题调用 `sort_by_jif_and_select` 选择代表文献，再结合 `fetchPMCArticleDetails` 或 `fetchPubmedArticleDetails` 补充细节。
6. 输出 Markdown 报告，至少包含：研究概览、热点主题、每个主题的代表关键词、代表文献与后续建议。

## Output Contract

- 主输出：一份 Markdown 热点分析报告。
- 必含字段：`topic overview`、`hotspot topics`、`supporting papers`、`next-step suggestions`。
- 推荐每个热点至少配 2-3 篇代表文献，并说明该主题为何属于热点。
- 如果检索覆盖不足，必须显式标记 `PARTIAL`。

## Failure Handling

- 文献检索结果过少：先扩大时间范围或放宽关键词，再说明覆盖不足。
- 关键词聚类不稳定：展示高频关键词并说明主题聚类仅为候选，不要强行下结论。
- 代表文献缺少可用细节：保留 PMID 和标题，标记为待补充。

## User Checkpoints

- 在开始大范围检索前，先确认主题边界和时间范围。
- 在输出最终热点报告前，如果聚类主题存在明显歧义，先把候选主题发给用户确认。

## Tools
*   `fetchPMCArticleDetails`: Get article details.
*   `fetchPubmedArticleDetails`: Get PubMed details.

## Scripts
*   `scripts/analysis_ops.py`: Contains helper functions for PubMed search, frequency analysis, keyword matching, and result formatting.

## References
*   `references/prompt_templates.md`: Contains the system prompts for LLM analysis.

## Quick Validation

- 检查 `scripts/analysis_ops.py` 是否存在，并确认至少能执行检索、词频和匹配三个核心步骤。
- 检查最终报告是否包含热点主题和对应代表文献，而不是只有关键词列表。
- 检查每个热点主题是否有明确的证据来源支撑。
