MODULE 01

已搭建 Skills 与 Tools 能力总览

1总编排 Skill：负责入口识别、路由、确认点和产物衔接
12业务 Skills：覆盖选题、文献、设计、伦理、执行、数据、统计、写作、投稿
90+原子 Tools：按 12 个 Skills 分层管理，鱼骨图展开核心与扩展工具簇
R0-R3风险等级：定义 Agent 可自动执行、需确认执行、禁止自动越权的边界

R0 · 只读解释

不改变用户资产，不产生正式产物

适用于概念解释、流程说明、术语翻译、普通问答。Agent 可以直接回答。

  • 典型动作：解释 PICOS、讲清楚 Cox/Logistic 区别
  • 确认要求：无需确认
  • 输出属性：参考性说明，不作为最终科研文件

R1 · 草案生成

生成建议或草稿，但不直接替用户定稿

适用于选题草案、综述框架、写作提纲、投稿建议等低风险规划任务。

  • 典型动作：生成 3 个选题、初版综述大纲、期刊候选列表
  • 确认要求：关键方向进入下一步前需要用户确认
  • 输出属性：草案/建议，可修改后继续

R2 · 影响研究决策

会影响方案、伦理、数据、统计路径

适用于研究设计、纳排标准、样本量、清洗策略、算法选择等会影响结果可信度的任务。

  • 典型动作：确定研究类型、生成 CRF、制定清洗规则、推荐统计方法
  • 确认要求：必须中断确认后再执行下一步
  • 输出属性：正式方案前置材料，需要留痕

R3 · 正式产物/外部动作

可能产生正式提交、外发、不可轻易回滚的结果

适用于正式统计运行、伦理/注册材料导出、投稿包、审稿回复、外部平台操作。

  • 典型动作：执行最终分析、导出伦理包、生成投稿包、准备 Response Letter
  • 确认要求：必须显式确认；外部系统动作需再次确认
  • 输出属性：正式交付物，需版本记录与责任边界说明

MODULE 03

用户意图如何调用 Skills 与 Tools

INPUT 01

用户原始输入

截取用户说法中的疾病、科室、研究对象、已有问题或具体诉求。

例：我想做肺癌预后研究
INPUT 02

已有材料状态

判断用户手里是否已有题目、文献、Protocol、伦理、数据、结果或初稿。

材料越完整，路由越靠后
INPUT 03

科研流程阶段

把用户定位到论文真实流程：选题、综述、设计、伦理、执行、数据、统计、写作、投稿。

映射 F-01～F-12
INPUT 04

当前任务目标

识别用户是要解释、生成草案、做正式方案、执行分析，还是准备投稿/外部提交。

决定调用哪些 Tools
INPUT 05

风险与缺失信息

判断 R0-R3 风险等级，并列出必须追问的信息；R2/R3 先确认再继续。

控制越权与误执行

Agent Plan + ReAct 执行过程

先规划，再调用工具；每次工具返回后观察结果，必要时重规划或中断确认
PLAN

任务规划

根据用户输入状态判断阶段、目标、缺失信息和风险等级。

输出：调用计划 / 追问清单 / 是否暂停确认
ACT

调用 Skills / Tools

选择主 Skill，并按需调用辅助 Skill 与具体 Tools。

输出：热点、PICOS、清洗报告、统计结果等中间产物
OBSERVE

观察工具结果

检查返回结果是否完整、一致、可信，是否触发 R2/R3 风险。

输出：证据状态 / 缺口 / 冲突 / 异常
RE-PLAN

重规划或确认

若信息不足则追问；若方向关键或风险较高，则暂停等待用户确认。

输出：修改后的调用链 / 用户确认点
DELIVER

交付与衔接

生成最终交付物，并给出下一步可衔接的科研任务。

输出：文档、报告、代码包、投稿包或下一任务入口

命中现有 Skills

直接进入主 Skill，并按需补调辅助 Skill。R2/R3 节点必须暂停确认后再继续。

示例：“缺失值怎么处理？” → F-06 数据清洗 → profile_data_quality / execute_cleaning_plan
示例：“投哪个期刊？” → F-12 期刊投稿 → rank_journal_fit / build_submission_checklist

未命中现有 Skills

先告诉用户当前意图不在已搭建 Skills 范围内，并询问是否启用外部工具或由 AI 基于通用知识生成草案。

外部工具：需要实时数据库、医院系统、投稿平台、伦理平台、检索平台时调用。
AI 自生成：适合解释、模板、通用建议；必须标注“非外部验证结果”。

未匹配怎么办

先追问，不硬生成

如果疾病/领域缺失，先追问；如果热点检索无结果，扩大检索范围并提示 PARTIAL；如果没有数据集，只按“无数据支撑”评分。

01

PLAN · 识别用户状态与任务边界

LLM / Orchestrator
输入用户原话：我是呼吸科，想做肺癌方向论文，但不知道选什么题。
调用 Skillzhangshu-research-orchestrator
调用 Tool无；先做意图识别与缺失信息判断。
输出阶段=零基础启动；目标=选题规划；缺失=研究类型/目标期刊/是否有数据。
02

ACT · 获取领域热点与研究空白

Skill / Tool
输入疾病=肺癌；科室=呼吸科；目标=临床科研创新选题。
调用 SkillF-01 选题规划：zhangshu-plan-topic
调用 Toolget_field_hotspot；必要时调用 F-02 search_literature_databases 辅助验证。
输出近三年热点方向、顶刊关注点、临床争议、证据空白候选清单。
03

ACT · 构建初步 PICOS 与数据可行性判断

ReAct / Parallel
输入热点候选清单 + 用户科室背景 + 可能已有数据条件。
调用 SkillF-01 选题规划；辅助总编排查询用户历史数据状态。
调用 Toolbuild_picos_frame；query_dataset_inventory；validate_design_logic 可选。
输出标准化 PICOS 草案、逻辑冲突项、数据支撑强弱判断。
04

OBSERVE · 检查方向是否可继续

Observation
输入热点证据 + PICOS 草案 + 数据条件。
调用 SkillF-01 内部规则；F-02 文献综述辅助证据校验。
调用 Tooldetect_debate_and_gap；verify_review_citations 可选。
输出可行方向、过热方向、证据不足方向、PICOS 冲突说明。
05

CONFIRM · 用户确认研究方向

R1/R2 确认点
输入热点摘要、PICOS 草案、推荐方向、风险说明。
调用 Skill不调用新 Skill；进入用户确认断点。
调用 Tool无；等待用户确认/修改疾病亚型、研究类型、数据范围。
输出用户确认方向；若不满意，退回节点 02 重新挖掘热点。
06

ACT + DELIVER · 生成三套选题方案

Skill / Deliver
输入已确认方向 + PICOS + 热点空白 + 数据可行性。
调用 SkillF-01 选题规划；下一步可衔接 F-03 研究设计。
调用 Toolcalculate_innovation_score；generate_topic_plan。
输出创新型/稳妥型/热点型三套选题、评分、初步研究大纲、下一步建议。
最终交付：选题方案报告、PICOS、创新可行性评分、初步研究大纲；下一步建议进入 F-02 文献综述或 F-03 研究设计。
CASE 02 · 数据清洗与统计分析任务

从原始 Excel 到可复现 Verified Result

代表统计攻坚期：用户已有原始数据，但不知道数据能否直接分析、该选什么模型、结果是否可信。

主 Skill：F-06 / F-08辅助：F-07 / F-09风险：R2→R3
LLM 做什么

拆解任务与解释结果

判断用户不是单纯问答，而是“清洗+算法+统计执行”链路；用临床语言解释缺失、异常、模型结果和局限性。

SKILLS 做什么

控制数据到结果流程

F-06 管清洗规则，F-07 管算法推荐，F-08 管统计执行和可复现结果，F-09 可继续生成图表。

TOOLS 做什么

处理数据和运行模型

inspect_dataset_schema、profile_data_quality、execute_cleaning_plan、generate_analysis_plan、execute_statistical_model。

未匹配怎么办

缺工具则不伪造统计结果

如果数据文件无法读取，要求重新上传；如果缺少统计执行环境，只能生成分析计划；如果需外部数据库，先请求授权。

01

PLAN · 判断数据任务类型

LLM / Orchestrator
输入用户原话：我上传了患者 Excel，帮我看看能不能直接分析，最好跑出结果。
调用 Skillzhangshu-research-orchestrator
调用 Tool无；先拆分为数据清洗、算法推荐、统计执行三段。
输出阶段=数据预处理/统计分析；风险=清洗 R2，正式运行 R3。
02

ACT · 识别数据结构

Skill / Tool
输入原始 Excel/CSV；字段名、取值、患者记录。
调用 SkillF-06 数据清洗：zhangshu-clean-clinical-data
调用 Toolinspect_dataset_schema；profile_data_quality。
输出字段类型、缺失率、异常值、日期逻辑、重复记录、关键变量完整性。
03

OBSERVE · 判断数据是否可分析

Observation
输入数据质量画像和异常检测结果。
调用 SkillF-06 数据清洗规则；必要时调用 F-03 校验研究变量定义。
调用 Tooldetect_data_issues；preview_cleaning_impact。
输出可分析/不可分析判断、必须修复字段、清洗影响预估。
04

CONFIRM · 确认清洗策略

R2 确认点
输入缺失值处理、异常值处理、变量重编码、排除规则建议。
调用 SkillF-06 数据清洗
调用 Toolrecommend_cleaning_plan；等待确认后 execute_cleaning_plan。
输出用户确认清洗方案；若否决，退回节点 03 重新预览影响。
05

ACT · 推荐统计方法与分析计划

Skill / Tool
输入清洗后数据集 + 研究目的 + 变量类型 + 结局类型。
调用 SkillF-07 算法推荐：zhangshu-route-statistics
调用 Toolprofile_dataset；query_algorithm_registry；evaluate_method_fit；generate_analysis_plan。
输出推荐模型、适用理由、前提假设、分析计划草案。
06

CONFIRM · 确认正式分析计划

R2/R3 确认点
输入统计方法、协变量、亚组/敏感性分析、输出指标。
调用 SkillF-08 统计分析前置确认
调用 Toolvalidate_analysis_plan；check_model_assumptions。
输出用户确认正式运行；如果模型假设不满足，退回节点 05 换方法。
07

ACT + DELIVER · 执行模型并打包结果

Skill / Deliver
输入已确认分析计划 + 清洗后数据集 + 统计环境。
调用 SkillF-08 统计分析；可衔接 F-09 统计绘图。
调用 Toolvalidate_statistical_environment；execute_statistical_model；validate_result_bundle；package_analysis_code。
输出Verified Result、结果解释、可复现代码包、运行清单。
最终交付：数据质量报告、清洗规则、分析计划、统计结果、模型解释、可复现代码包；下一步可进入 F-09 统计绘图或 F-10 论文写作。
CASE 03 · 论文写作与投稿任务

从统计结果到论文初稿、目标期刊与投稿包

代表写作投稿期：用户已有结果资产，需要生成稿件、校验真实性、匹配期刊并准备投稿材料。

主 Skill：F-10 / F-12辅助：F-11风险：R1→R3
LLM 做什么

撰写和解释文本

根据结构化结果撰写 IMRAD、Cover Letter、回复说明，把期刊匹配理由转成用户能理解的投稿策略。

SKILLS 做什么

控制写作投稿流程

F-10 管论文写作与声明材料，F-11 管参考文献格式，F-12 管选刊、投稿清单和投稿包校验。

TOOLS 做什么

校验与匹配

collect_verified_artifacts、validate_result_citations、format_reference_set、rank_journal_fit、validate_submission_package。

未匹配怎么办

没有结果资产则不能写正式稿

如果没有 Verified Result，只能生成写作框架；如果无期刊库/外部检索权限，只能给候选策略并标注未验证。

01

PLAN · 判断写作资产是否齐全

LLM / Orchestrator
输入用户原话：统计结果跑完了，帮我整理成论文，再看看能投哪个期刊。
调用 Skillzhangshu-research-orchestrator；F-10 前置检查。
调用 Toolcollect_verified_artifacts。
输出已有资产清单：结果、图表、方法、伦理信息、参考文献；缺失项列表。
02

ACT · 生成论文结构与 IMRAD 初稿

Skill / LLM
输入Verified Result、研究设计、方法学说明、目标文章类型。
调用 SkillF-10 论文写作：zhangshu-write-manuscript
调用 Toolselect_manuscript_template；draft_imrad_section；generate_statistical_tables。
输出论文标题、摘要、IMRAD 初稿、表格草案。
03

OBSERVE · 校验数字、引用与声明

Observation / Tool
输入论文初稿 + 统计结果包 + 引用集合 + 伦理信息。
调用 SkillF-10 论文写作；F-11 文献格式化。
调用 Toolvalidate_result_citations；check_manuscript_compliance；format_reference_set；validate_reference_set。
输出数字一致性检查、引用问题、伦理/数据可用性声明缺口。
04

CONFIRM · 用户确认初稿与投稿偏好

R1/R2 确认点
输入论文初稿、问题清单、候选投稿方向需要的信息。
调用 Skill不执行外部动作；进入确认断点。
调用 Tool无；收集目标分区、审稿周期、OA/APC、是否避开预警期刊。
输出用户确认初稿方向和投稿偏好；若不满意，退回节点 02 重写相关章节。
05

ACT · 匹配目标期刊并评估风险

Skill / Tool
输入稿件画像、研究领域、文章类型、用户投稿偏好。
调用 SkillF-12 期刊投稿：zhangshu-match-journals
调用 Toolextract_manuscript_profile；query_journal_database；rank_journal_fit；assess_submission_risk；check_apc_and_oa_risk。
输出候选期刊排序、匹配理由、风险提示、投稿优先级。
06

CONFIRM · 确认目标期刊与投稿包

R3 确认点
输入目标期刊、投稿清单、Cover Letter、声明材料。
调用 SkillF-12 投稿前确认；F-10 写作辅助生成文书。
调用 Tooldraft_cover_letter；build_submission_checklist。
输出用户显式确认目标期刊和材料；外部投稿动作必须二次确认。
07

DELIVER · 投稿包校验与导出

Skill / Deliver
输入最终稿、图表、参考文献、Cover Letter、声明材料。
调用 SkillF-12 期刊投稿；F-11 文献格式化。
调用 Toolvalidate_submission_package；build_submission_checklist；format_reference_set。
输出投稿包、材料缺口检查、期刊格式校验、提交前清单。
最终交付：论文初稿、参考文献格式化结果、目标期刊列表、Cover Letter、投稿材料清单、投稿包校验报告；外部提交需用户二次确认。
CASE 04 · 未匹配意图 / 无可调用工具

从“不确定怎么做”到追问、外部工具或 AI 兜底

代表异常边界：用户输入无法匹配现有意图，或命中了任务但当前没有可调用 Tool，Agent 不能假装已经执行。

主控：总编排可选：外部工具风险：R0→R3
LLM 做什么

判断不确定性来源

判断是用户表达不完整、意图不在覆盖范围内，还是命中了意图但当前缺少可调用工具。

SKILLS 做什么

总编排控制边界

不进入具体业务 Skill，先由总编排输出追问、边界说明、可选外部工具或 AI 草案路径。

TOOLS 做什么

仅在授权后调用

需要实时数据库、医院系统、投稿平台、伦理平台或检索平台时，必须先获得用户授权。

未匹配怎么办

追问/说明/授权/标注

信息不足先追问；能力不覆盖则说明边界；无工具时不能假装执行；AI 兜底必须标注未外部验证。

01

PLAN · 识别是否命中已有意图

LLM / Orchestrator
输入用户原话：帮我处理一下这个科研相关问题，但没有说明阶段、材料和目标。
调用 Skillzhangshu-research-orchestrator；用户意图路由规则。
调用 Tool无；先做意图分类、材料状态判断、风险等级判断。
输出命中/未命中状态；缺失信息清单；可能候选路径。
02

OBSERVE · 判断是信息缺失还是能力缺失

LLM / Rule
输入候选意图、已有材料、用户目标、当前可用 Skills/Tools 列表。
调用 Skill总编排 Skill；不进入具体业务 Skill。
调用 Toolskill/tool registry 检查；确认是否有对应工具可执行。
输出分类结果：A 信息不足；B 意图不覆盖；C 意图覆盖但工具不可用；D 需要外部实时系统。
03

RE-PLAN · 信息不足时先追问

LLM
输入缺失字段：疾病/阶段/材料/目标/是否有数据/是否要正式导出。
调用 Skill不调用业务 Skill；停留在总编排追问。
调用 Tool无。
输出向用户提出最少必要问题；用户补充后回到节点 01 重新路由。
04

RE-PLAN · 意图不覆盖时说明边界

Boundary
输入用户任务不在当前 12 个业务 Skills 范围内。
调用 Skill总编排 Skill 输出边界说明。
调用 Tool无；不得伪造工具执行结果。
输出告知“当前未覆盖该任务”；提供可选方案：外部工具、人工处理、AI 通用草案。
05

CONFIRM · 需要外部工具时先授权

R2/R3 确认点
输入任务需要实时数据库、医院系统、投稿平台、伦理平台、检索平台或第三方 API。
调用 Skill总编排 Skill；可能衔接外部连接器。
调用 Tool外部检索/平台 API/浏览器/数据库接口；仅在用户授权后调用。
输出用户确认是否启用外部工具；未授权则不能调用外部系统。
06

DELIVER · 无工具时 AI 只能生成标注草案

LLM / Fallback
输入用户允许 AI 基于通用知识给建议，但没有可验证工具或外部来源。
调用 Skill无业务 Skill 强制执行；总编排负责加免责声明。
调用 Tool无。
输出通用建议/模板草案；必须标注“未经过外部验证，不能作为正式科研结论”。
最终规则：没有识别到用户意图时先追问；没有对应 Skill/Tool 时说明能力边界；需要外部工具时先征得授权；AI 自生成只能作为草案，必须明确标注未验证。
